## Project Overview

**Hum Producer** — an AI music production web app. Users hum a melody, AI analyzes it (key/tempo/mood/genre), generates a full arrangement, then users add layers via voice or text commands. Built for ListenHacks hackathon.

## Commands

```bash
npm run dev      # Start dev server (localhost:3000)
npm run build    # Production build
npm run lint     # ESLint
```

No test framework is configured.

## Architecture

**Next.js 16 App Router** with TypeScript, Tailwind CSS v4, and shadcn/ui components.

### Data Flow

1. **Record** → `HumRecorder` captures mic audio as WebM blob
2. **Analyze** → `/api/analyze-hum` sends audio to Gemini 3.5 → returns `MusicalAnalysis` (key, tempo, mood, genre)
3. **Generate** → `/api/generate-track` sends analysis to Beatoven.ai → polls for completion → returns MP3 URL
4. **Studio** → `TrackList` displays all tracks with waveforms; users add layers via `VoiceCommandBar` or `TextCommandBar`
5. **Add layers** → Voice commands parsed by Gemini (`/api/voice-command`), audio generated by ElevenLabs (`/api/generate-beat`)
6. **Export** → `Mixer.exportMix()` renders all tracks via `OfflineAudioContext` → downloads WAV

### Key Modules

- **`src/store/tracks.ts`** — Zustand store holding all app state: current step (`record`→`analyzing`→`generating`→`studio`), tracks array, analysis results, playback state. AudioBuffers are stored in-memory (not serializable).
- **`src/lib/mixer.ts`** — Singleton `Mixer` class managing Web Audio API playback. Handles solo/mute logic, per-track gain nodes, and offline rendering for export.
- **`src/lib/audio-utils.ts`** — Conversions between Blob, base64, AudioBuffer, and WAV format. `getAudioContext()` returns a shared singleton AudioContext.
- **`src/types/music.ts`** — Core types: `Track`, `MusicalAnalysis`, `VoiceCommand`, `AppStep`.

### API Routes (all under `src/app/api/`)

| Route | External API | Purpose |
|-------|-------------|---------|
| `analyze-hum` | Gemini 3.5 Flash | Audio → musical analysis JSON |
| `generate-track` | Beatoven.ai | Analysis → full arrangement MP3 (polls up to 120s) |
| `voice-command` | Gemini 3.5 Flash | Audio → parsed command JSON |
| `generate-beat` | ElevenLabs Sound Generation | Text description → audio (base64 MP3) |
| `proxy-audio` | passthrough | Proxies external audio URLs to avoid CORS |

### Environment Variables (`.env` or `.env.local`)

- `GEMINI_API_KEY` — Google Generative AI (used by analyze-hum and voice-command)
- `BEATOVEN_API_KEY` — Beatoven.ai track generation
- `ELEVENLABS_API_KEY` — ElevenLabs sound generation

### Important Patterns

- All AI/external API calls go through server-side API routes — never expose keys client-side.
- Audio flows: browser records WebM → converted to base64 for Gemini → AudioBuffers decoded client-side for playback/waveforms.
- Beatoven.ai is async: POST creates a task, then poll GET until `status === "composed"`.
- WaveSurfer.js renders waveforms from AudioBuffer channel data, not from URLs.
- Components conditionally render based on `step` from the Zustand store.
